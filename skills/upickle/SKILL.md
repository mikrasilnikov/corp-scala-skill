# upickle

Producers publish the JSON Schema of their payloads with upickle-jsonschema, and consumers on upickle need case classes that read those payloads. upickle's derived readers already handle every shape the generator emits: optional fields, longs, tagged sealed families, keyed maps. Your job is to choose the types; the derived `ReadWriter`s do the reading. The rules below apply to every such conversion.

The shapes upickle-jsonschema 4.4.3 emits, the full shape-to-type table for Scala 2.13 and 3, the `$defs` naming rules, the pickler configurations, and a worked example with its test and report are in [references/schema-mapping.md](references/schema-mapping.md). Read it when a shape is not in the tables below, when you translate Scala 3 producer source for a Scala 2 consumer, or when you need the full example.

## Before generating

**Ask once for the producer's source.** Before you generate anything, ask the user whether the Scala source the schema was generated from is available, and wait for the answer. If the conversation already answers it, take that answer instead of asking. Ask once per schema and task, never again. Use only the files or repository the user points you at: do not search the machine or the network for the producer.

**With source, mirror it; the schema decides the shapes.** For every `$defs` entry you need, reproduce the producer's definition: class, field, and case names, nesting, type parameters, default values, `@key` and `@allowUnknownKeys` annotations, narrow scalar types such as `Short`, `Float`, `Char`, `java.util.UUID`, or `BigDecimal`, and any custom pickler the producer uses for a type the schema reaches. Mirror field and case names in meaning, but spell them as the mapping rules below require, lowerCamelCase for a field and UpperCamelCase for a case, with `@key("<producer name>")` carrying the producer's spelling where it differs: a producer's `total_count: Int` becomes `@key("total_count") totalCount: Int`, and its `case object in_progress` becomes `@key("in_progress") case object InProgress`. Translate to the consumer's Scala version: for a Scala 2 consumer, a Scala 3 `enum` becomes a `sealed trait` with case objects and case classes of the same names in its companion ([section 6](references/schema-mapping.md#6-translating-scala-3-producer-idioms-to-scala-213)). The schema still decides which definitions are needed and what each shape is, because it is the published contract and the source you have may be another version. The one exception is a producer type whose schema the generator misdescribes ("Shapes the generator misdescribes" below): take from the source only what that rule takes, such as a named tuple's names or a map's key type with its definition, and list the property under `Generator defects:`, not as a disagreement; a sample payload that contradicts the source decides instead. Every other mismatch between a producer field's type, item or value type, or default and the schema's shape is a disagreement: follow the schema and name it in your report. When the user supplies source for part of the schema only, mirror that part, derive the rest from the schema, and say in the report which definitions came from where.

**Without source, derive from the schema.** Names, nesting, type parameters, and defaults then come from the schema, and from a sample payload only where the rules below say so, and you do not ask again.

**upickle must already be declared.** Before writing any definition, confirm that `com.lihaoyi::upickle` is declared for the target module, directly or through a module it depends on, by reading the build definition or running a read-only build query. If no declaration reaches the module, stop and ask the user to add it, and the task pauses there:

```text
Dependency request
Coordinates:   com.lihaoyi %% upickle % <version, if known>
Module:        <module>
Configuration: Compile
Reason:        the generated definitions for <root type> derive upickle ReadWriters
```

Never add upickle, a JSON Schema validator, a test framework, or any other library yourself, even when a validator would make checking easier: the unit test below is the check.

**Derivation follows the module's Scala version.** Read `scalaVersion` and `crossScalaVersions` for the module from the build definition.

| Module | Case classes | Families |
|---|---|---|
| Scala 3 only | `case class X(...) derives ReadWriter` | `enum X derives ReadWriter`; both families of a sub-family are `sealed trait X derives ReadWriter` |
| Scala 2.13 or 2.12, or `crossScalaVersions` with a Scala 2 version | `implicit val rw: ReadWriter[X] = macroRW` in the companion | `sealed trait X`, the same `implicit val` in its companion |

On Scala 2, also give each case object `implicit val rw: ReadWriter[X.type] = macroRW` in its body, give a generic definition `implicit def rw[T: ReadWriter]: ReadWriter[X[T]] = macroRW`, and use `implicit lazy val` for every definition that refers to itself, directly or through another definition. The Scala 2 form compiles on Scala 3 as well, which is why a cross-built module uses it. If the module already has its own pickler configuration, an object extending `upickle.AttributeTagged` or another `upickle.Api`, derive from that object (`derives MyApi.ReadWriter`, `MyApi.macroRW`) rather than from `upickle.default`.

**Put the definitions where the module keeps its models.** Generate a definition for each `$defs` entry reachable from the document's root, directly or through other entries, except an entry the rules below give no definition of its own (a tuple entry, a `prefixItems` entry in a hand-written document, and the `scala.util.Either`, `Left`, and `Right` entries), and nothing for an unreachable entry. Place them, and any map key type mirrored from the source, in the package and directory that hold the module's case classes, in one file named after the root type. If the module has no such place, ask the user where to put them before writing.

## Mapping shapes to types

**The optional shape is `Option[T]`, and nothing else is written for it.** One schema S plus `{"type": "null"}`, with or without an array of zero or one items of S, is `Option[T]`, where T is the mapping of S. upickle-jsonschema emits it as:

```json
{"anyOf": [S, {"type": "null"}, {"type": "array", "minItems": 0, "maxItems": 1, "items": S}]}
```

The array alternative is part of the optional shape, never a collection and never a case to handle. It is upickle's boxed form, used only for nested options and by producers configured with `optionsAsNulls = false`: a default producer never writes it at the first level, and a default consumer could not read it there, so code for it is dead. An optional shape whose S is itself the optional shape is `Option[Option[T]]`, which upickle boxes and unboxes itself, unless the inner shape is a type argument's: `example.R[scala.Option[scala.Int]]` whose `data` has the nested shape is `case class R[T](data: Option[T])`, read as `R[Option[Int]]`, because upickle writes that generic field unboxed, as `3` or `null`; list `data` under `Generator defects:`. Hand-written nullable forms are the same shape: `{"type": ["string", "null"]}` and `{"anyOf": [{"type": "string"}, {"type": "null"}]}` are both `Option[String]`. A plain `{"type": "array", "minItems": 0, "maxItems": 1, "items": S}` with no null alternative means a producer running with `optionsAsNulls = false`: the field is still `Option[T]`, every generated `ReadWriter` derives from a pickler configuration object that sets `optionsAsNulls = false` ([section 7](references/schema-mapping.md#7-producer-configurations-boxed-options-and-renamed-tags)), and your report names that configuration.

**`required` decides defaults, independently of `Option`.** upickle-jsonschema puts every field without a default value in `required`, and never writes the default itself.

| Property | In `required` | Not in `required` |
|---|---|---|
| Optional shape | `next: Option[Node]`, no default | with source, the producer's default, `timeout: Option[Int] = Some(30)`; without, `simple2: Option[SimpleEnum] = None` |
| Any other shape | `i: Int`, no default | with source, the producer's default, `s: String = "x"`; without, `s: Option[String] = None`, named in the report |

Never invent a default such as `0`, `""`, or `Nil`: a value the producer did not send reads as `None` or fails. Under an `optionsAsNulls = false` pickler, `Option[T] = None` cannot stand in for an unknown default either: that pickler reads an `Option` only from an array, while the producer writes the field's bare value, so ask the user for the default of each such field.

**Other shapes.**

| Schema | Scala type |
|---|---|
| `{"type": "integer"}` | `Int` |
| `{"type": "number"}` | `Double` |
| `{"type": "boolean"}` | `Boolean` |
| `{"type": "string"}` | `String` |
| `anyOf` of `{"type": "integer"}` and `{"type": "string", "pattern": "^-?(0\|[1-9][0-9]*)$"}` | `Long` |
| `{"type": "string", "pattern": "^-?(0\|[1-9][0-9]*)$"}` | `BigInt` |
| `{"type": "null"}` | `Unit` |
| `{}` | `ujson.Value` |
| `array` with `items` S | `Seq[T]`, or `Set[T]` with `"uniqueItems": true` |
| inline `array` with `prefixItems` and equal `minItems` and `maxItems` | a tuple, such as `(Double, Double)`; a pair could be a named tuple (below) |
| `object` with `additionalProperties` S and no `properties` | `Map[K, T]`, K by `propertyNames`: none `String`, integral pattern `Long`, `^(true\|false)$` `Boolean`, length 1 `Char`, `"format": "uuid"` `java.util.UUID` |
| `{"$ref": "#/$defs/<key>"}` | the definition generated for that key, or the tuple or `Either` the key stands for (below) |

`Int`, `Double`, `String`, `Seq`, and the `Long` key are defaults: the schema cannot tell them from `Short`, `Byte`, `Float`, `Char`, `java.util.UUID`, `BigDecimal`, `List`, `Vector`, or another integral key. In upickle-jsonschema output, `(A, B)` for an inline pair and `Map[String, T]` for a map without `propertyNames` are defaults too, when nothing settles them (below). With source, use the producer's narrow type; without, name each such property in the report.

**Objects with `properties` become case classes.** One constructor field per property, in the schema's property order. A property name that is already lowerCamelCase is the field name verbatim, with no `@key`: `firstName`, `totalCount`. Any other gets a lowerCamelCase field name and `@key("<property>")`: `@key("first_name") firstName: String`, `@key("content-type") contentType: String`. `"additionalProperties": false` adds `@allowUnknownKeys(false)` to the class, and `true` adds nothing. An object with no properties is an empty case class, `case class Ping()`.

**Unmapped shapes are `ujson.Value`.** A property matching none of these shapes, such as a `oneOf` of `string` and `integer` without a tag, or one using `patternProperties`, is `ujson.Value`. A `string` with a `format` not named here, such as `date-time`, stays `String`: upickle has no `java.time` readers. Name every such property in the report, with its `format` where it has one, and never guess a narrower type.

### Names from $defs keys

Without source, each reachable `$defs` entry that gets a definition is named from its key, which upickle-jsonschema writes as the Scala type's full name. A key in the `scala` package is never named this way: it is a tuple, a named tuple, or an `Either`, and follows the rules for those. A `definitions` section and `#/definitions/...` references are read exactly as `$defs`.

- The name is the last dotted segment before any `[`: `com.acme.billing.Invoice` is `Invoice`.
- Capitalised segments before it are enclosing objects: `upickletest.ColorEnum.Mix` is `Mix`, nested in the companion of `ColorEnum`.
- Segments starting with a lowercase letter are the producer's package. Use the consumer's package instead: no `com.acme.billing` appears in the generated code.
- A type argument becomes a type parameter when the argument's schema is a property's schema in that entry, or the S of a property's optional, array, or map shape: `example.ApiResult[example.Person]` whose `data` is the optional shape over `{"$ref": "#/$defs/example.Person"}` is `ApiResult[T]` with `data: Option[T]`, and the root is read as `ApiResult[Person]`. Several instantiations of one constructor, such as `example.Box[scala.Int]` and `example.Box[scala.Predef.String]`, share one generic `Box[T]`.
- When no property uses the argument, the definition is concrete: `example.Marker[example.Foo]` is `Marker`, and a second instantiation, `example.Marker[example.Bar]`, is `MarkerBar`.
- A `scala.Tuple<N>[...]` key, or `scala.*:[...]` for a tuple written with `*:`, is the tuple of its `prefixItems`: the property that refers to it takes the tuple type, `(Int, String, Boolean)`, and no definition is generated.
- A `scala.NamedTuple.NamedTuple[...]` key is a case class with the named tuple's names as fields, typed by its properties, and named, capitalised and camel-cased, after the property that refers to it (`position` gives `Position`) or, for a type argument of a generic definition, after the property typed with that instantiation (`point: Box[Point]`). When several properties qualify, the first, in the order of the referring entries and of their properties, names it; when only the root refers to it, its field names joined do (`XYZ`).

### Shapes the generator misdescribes

For six producer types, upickle-jsonschema 4.4.3 emits a schema that does not describe what upickle writes. Generate the type that reads what upickle writes, list it under `Generator defects:` in the report, and test it with a document in that form. These rules apply only to upickle-jsonschema output: the user says the schema came from it, or its `$defs` keys are Scala type names with dotted package paths or `scala.` type arguments. In a hand-written document a pair is a pair, a string-keyed map is a map, and neither is reported.

**Inline pairs.** An inline two-item `prefixItems` array is a pair, unless a named tuple is shown there, which upickle writes as an object, `{"x": 1, "y": 2}`. The producer's source (`point: (x: Int, y: Int)`), a sample payload (`"point": {"x": 1, "y": 2}`), or an enclosing `$defs` key that prints `scala.NamedTuple.NamedTuple[scala.Tuple2["x", "y"], ...]` for it shows one; then the pair is a case class with the named tuple's names as fields, typed by the items in order and named as a named-tuple entry is: `point: Point`, or `point: Box[Point]` through the key. Where the source and a payload disagree, the payload decides and the report names the disagreement. A key that prints `scala.Tuple2[...]` settles a plain pair. When nothing settles it, keep the pair and name the property under `Defaults and fallbacks:` as a pair that could be a two-field named tuple.

**Positional case classes.** A `$defs` entry that is an `array` with `prefixItems` and equal `minItems` and `maxItems`, keyed outside the `scala` package, is a case class with the fields `_1` to `_N`: `example.Pair` is `case class Pair(_1: Int, _2: String)`, which reads the `{"_1": 1, "_2": "a"}` upickle writes. In a hand-written document such an entry is the tuple of its items, with no definition.

**`Either`.** A `scala.util.Either[...]` entry, a `oneOf` over `scala.util.Left[...]` and `scala.util.Right[...]` entries whose only property is `value`, is `Either[A, B]` of the two `value` types, not a sealed family, and none of the three entries gets a definition: upickle writes `[0, a]` or `[1, b]`.

**Sealed sub-families.** A `oneOf` case that is an `allOf` of a `$ref` to another `oneOf` entry and a tag `const` is a sub-family. upickle never writes that `const`: it writes the inner case's tag. Declare both families as `sealed trait`s, the inner extending the outer, on every Scala version, put `@key("<tag>")` on every case of both families, and write no case for the outer `const`: `sealed trait Event` with `@key("Ping") case object Ping`, `sealed trait UserEvent extends Event`, and `@key("Created") case class Created(id: Int) extends UserEvent`.

**Maps keyed by other types.** upickle writes a map as an object only when its key type is one it writes as an object key: strings, `Symbol`, `Char`, `Boolean`, `Unit`, `java.util.UUID`, the numeric types with `BigInt` and `BigDecimal`, `Duration`, and types wrapped in `stringKeyRW`. Any other key type, such as an enum or a case class, is written as `[key, value]` pairs under the same `additionalProperties` schema, and the key's own schema is not emitted. With source, take the producer's key type and mirror its definition: `counts: Map[Color, Int]` reads `[["Red", 1]]`. Without source, the map stays `Map[String, T]`, which also reads pairs whose keys are strings: name it under `Defaults and fallbacks:` as a map whose producer may use another key type, and when a sample payload shows pairs with keys that are not strings, ask the user for the key type.

**Generic options.** A nested optional shape inside a type argument stays `Option[T]` in the generic definition, as described under the optional shape above.

## Sealed families

**A tagged `oneOf` is a sealed family.** A `$defs` entry whose `oneOf` entries are each a bare `{"const": "<tag>"}` or an `allOf` of a `$ref` and an object requiring a tag property with a `const` is a sealed family, an `enum` on Scala 3 and a `sealed trait` on Scala 2, unless it is the `scala.util.Either` entry or holds a sub-family ("Shapes the generator misdescribes" above):

```json
{"oneOf": [
  {"const": "End"},
  {"allOf": [{"$ref": "#/$defs/example.LinkedList.Node"},
             {"type": "object", "properties": {"$type": {"const": "Node"}}, "required": ["$type"]}]}
]}
```

Each bare `const` is a case object, or a parameterless enum case, which upickle reads and writes as the bare string `"End"`. Each `allOf` entry is the case class generated for its `$ref`, read and written as an object carrying the tag, `{"$type": "Node", ...}`. Put every case in the family's companion, or in the `enum` body: upickle tags an enum case by its own name, and a sealed trait's case by its full name minus the prefix all cases share, so cases placed together get their simple names as tags, and those are the `const` values. A hand-written `{"enum": ["A", "B"]}` is a family of bare `const` entries: case objects `A` and `B`. A case class that refers back to its family through `$ref` refers to it directly, with no indirection added for the recursion.

**Cases are named by their tags.** When the tag is already UpperCamelCase, name the case exactly as its tag, with no annotation: `End`, `Node`. Otherwise name it in UpperCamelCase and keep the tag with `@key("<tag>")` on the case: `@key("in_progress") case object InProgress`, or `@key("in_progress") case InProgress` in an `enum`, and `@key("reddit.com") case object RedditCom` for a tag that is not a legal Scala name. A tag property other than `$type` goes on the family: when the `allOf` entries require `kind`, the family is `@key("kind") sealed trait ...` or `@key("kind") enum ...`, and its cases are otherwise unchanged. With source that shows the producer overriding `tagName` in its pickler configuration, mirror that configuration instead ([section 7](references/schema-mapping.md#7-producer-configurations-boxed-options-and-renamed-tags)). Write no code that reads the tag.

## Never write by hand

**Derived readers do all the reading.** For every shape the mapping covers, write none of these:

- a custom `Reader`, `Writer`, or `ReadWriter`;
- `readwriter[ujson.Value].bimap`, or any other `bimap` over `ujson.Value`;
- a field read into `ujson.Value` and then dispatched over its `anyOf` or `oneOf` alternatives in code;
- a `visitNull` or `visitArray` override, or any other manual null or array check;
- code that reads, checks, or dispatches on a family's tag.

If you catch yourself considering one of these for the optional shape, declare the field `Option[T]` and write nothing else for it. A `Long` that the schema allows as an integer or a string is `Long`, with no reader for the string; a tagged `oneOf` is a sealed family, with no tag reader.

**Two pieces of code are permitted, and both are named in the report.** A pickler configuration object that mirrors a producer's non-default `optionsAsNulls` or `tagName`, from which every generated `ReadWriter` derives. And a custom pickler reproduced from the producer's source for a type the schema reaches, translated to the consumer's Scala version. Nothing else.

## Verifying and reporting

**A unit test reads documents into the root type.** Add a test, in the test framework the module already declares, that reads JSON documents into the generated root type and asserts on the values read:

- choose the documents by the type a field is declared with in the generated definition; a generic `Option[T]` instantiated with an `Option` counts as declared `Option[T]`;
- for each field declared `Option[T]`, `T` not an `Option`, a document with a value, one with `null`, and, where the field is not in `required`, one without the key, expecting `Some`, `None`, and the field's default, which is `None` unless the producer's source gives another, such as `Some(30)`;
- for each field declared `Option[Option[T]]`, in place of the value and `null` documents, the boxed documents upickle writes, `[x]`, `[null]`, and `[]`, expecting `Some(Some(x))`, `Some(None)`, and `None`, plus the one without the key where the field is not in `required`; never a bare `null`, which upickle reads there as a Scala `null`;
- when the types are read through an `optionsAsNulls = false` pickler, `[x]` and `[]` for an `Option[T]` field and `[[x]]`, `[[]]`, and `[]` for an `Option[Option[T]]` field, plus the one without the key; never a bare value or `null`, which that pickler rejects or reads as a Scala `null`;
- for a field made `Option[T] = None` because the schema carries no default, a document with a value and one without the key;
- for each sealed family, one document per case: the bare string for a singleton, the tagged object for a case class;
- for each entry under `Generator defects:`, a document in the form upickle writes, never the array or tagged form the schema shows: `{"_1": 1, "_2": "a"}` for a positional case class, `[0, 1]` and `[1, "s"]` for an `Either`, `{"x": 1, "y": 2}` for a named pair, `[["Red", 1]]` for a map keyed by an enum, `{"$type": "Created", "id": 1}` for a sub-family's case, `{"data": 3}` for a generic option;
- every sample payload the user supplies. A payload that fails to read is a defect in the generated definitions.

Derive the documents from the schema's own alternatives, such as a `Long` both as a number and as a string, rather than from what you assume the producer sends, except where the bullets above give the form upickle writes. If the module declares no test framework, ask for one in the dependency request shape above, with configuration `Test`; do not add it, and do not skip the test.

**Run the build and the tests the way the repository requires.** Compile and run the new test through the repository's own build, following its rules for running it. Never report the conversion as done while the build or the tests are unrun or failing.

**Report every default and ambiguity.** Report the finished conversion in this shape:

```text
Schema conversion done
Root type:     <type> in <package>, <file>
Source:        <mirrored from <path> | derived from the schema | mixed: <definitions> mirrored from <path>, the rest derived from the schema>
Files written: <each file written or changed>
Test:          <test class>, <number> documents
Build:         <command run>: <result>
Defaults and fallbacks:
  <Type.property>: <chosen type>; schema allows <alternatives>
Pickler configuration: <none | optionsAsNulls = false | tagName = "<name>">, <object, and any custom pickler reproduced from source>
Disagreements with source: <none | one line each: <Type.property>: source <type or default>, <schema <shape> | payload <form>>; followed <the schema | the payload>>
Generator defects: <none | one line each: <Type or Type.property>: schema <shape>, upickle writes <form>; generated <type>>
```

Under `Defaults and fallbacks:` list, one line each, every property resolved by a default or a fallback: `Int`, `Double`, `String`, or `Seq` for a shape that could be narrower, `Long` for integral map keys, in upickle-jsonschema output `(A, B)` for an inline pair and `Map[String, T]` for a map without `propertyNames` when nothing settles them, `Option[T] = None` for a default the schema does not carry, and `ujson.Value` or `String` for an unmapped shape. Under `Generator defects:` list every definition or property for which you followed what upickle writes over the schema. When a list is empty, write `none` after its label.
